# MEHLIST — Интерактивная Party-игра для вечеринок

Полнофункциональная party-игра для компании в духе Jackbox / Quiplash с разделением на главный экран (Host/ТВ) и экраны игроков на смартфонах (Controller), работающая в реальном времени через WebSockets. Игроки придумывают самые смешные ответы на провокационные и остроумные вопросы, а затем голосуют за победителя раунда.

> [!IMPORTANT]
> **Ключевые подтверждённые решения:**
> - **Формат взаимодействия**: Комнаты по 4-буквенному коду и QR-коду. Главный экран открывается на ноутбуке/ТВ, игроки подключаются со своих смартфонов. Также поддержан быстрый режим локального тестирования (добавление виртуальных игроков или локальное тестирование на одном устройстве).
> - **Категории и типы заданий**: Встроенная база заданий из файла `mehlist_b03b2d30.txt` с возможностью тонкой фильтрации тегов (`STANDARD`, `18+`, `FAMILY`) и типов раундов (`STANDARD` — один панчлайн, `THRIP` — блиц «3 вещи»), а также добавление собственных карточек и ИИ-генерация новых заданий.
> - **Визуальный стиль**: Экспрессивный неоновый party-game стиль в духе Jackbox/Quiplash с сочными акцентами, анимациями баттлов ответов, звуковыми эффектами (Web Audio API) и адаптивным мобильным контроллером.

---

## 1. Концепция и игровой процесс

### Роли и экраны:
1. **Главный экран ведущего (Host Screen / TV Mode)**:
   - Отображает крупный 4-значный код комнаты и QR-код для моментального входа с камеры телефона.
   - Список подключённых игроков в лобби с их аватарками и статусом готовности.
   - Настройки игры: фильтр тегов (`STANDARD`, `18+`, `FAMILY`), выбор типов вопросов (`STANDARD`, `THRIP`), длительность таймера (30/60/90 сек), количество раундов.
   - Фаза ответа: таймер обратного отсчёта и живой счётчик сдавших ответы игроков.
   - Фаза баттла (Showdown): эффектный вывод двух соперничающих ответов с анимацией и звуковым сопровождением.
   - Фаза оглашения результатов и начисления очков (Quiplash / Мех-очки, процент голосов, бонусы за сокрушительную победу).
   - Финальный пьедестал почета и сводная таблица лидеров с анимацией конфетти.

2. **Экран игрока (Mobile Controller)**:
   - Вход: ввод кода комнаты и ника, выбор весёлого аватара.
   - Фаза ввода: получение персонального задания (или 3 полей для типа `THRIP`), удобный ввод текста, кнопка «Отправить».
   - Фаза голосования: чтение вопроса и нажатие на понравившийся вариант ответа соперников (с блокировкой голосования за собственный ответ).
   - Интерактивные реакции в реальном времени: отправка смайлов/аплодисментов во время чтения ответов, которые летят по главному экрану.

## 2. Пользовательский интерфейс и дизайн-система

### Цветовая палитра и атмосфера (60-30-10):
- **Основной фон (60%)**: Глубокий тёмно-индиговый/графитовый фон (`#0D0F1D` / `#13162B`) с динамическими градиентными бликами.
- **Поверхности и карточки (30%)**: Карточки с высокой контрастностью (`#1E2242` и `#282D56`), чёткие границы `border border-indigo-500/20`.
- **Акценты действия (10%)**:
  - Неоновый жёлтый/лайм (`#FACC15` / `#EAB308`) — акцентные кнопки, таймеры, победители.
  - Сочный коралл/маджента (`#EC4899` / `#F43F5E`) — тег 18+, режим THRIP, эффектные вспышки голосования.
  - Электрический циановый (`#06B6D4` / `#38BDF8`) — тег FAMILY, подсказки, статус соединения.

### Типографика:
- **Заголовки и карточки**: `Plus Jakarta Sans` / `Outfit` с жирным начертанием `font-extrabold tracking-tight`.
- **Тексты ответов**: Крупный, легко читаемый с экрана ТВ шрифт с балансировкой переносов (`text-wrap: balance`).
- **Счётчики и таймеры**: Моноширинные цифры (`tabular-nums font-mono`).

### Аудиовизуальные эффекты (Web Audio API):
- Звуки тиканья последних 5 секунд таймера.
- Звук гонга/свистка при старте раунда.
- Звуки выбора голоса и триумфальные фанфары победителя раунда.
- Интерактивный тумблер включения/выключения звука в углу экрана.

## 3. Техническая архитектура и стратегия реального времени

Архитектура клиент-сервер на базе Node.js + Express + WebSocket (`ws`), смонтированного на едином порту 3000 в `server.ts` в соответствии с требованиями AI Studio full-stack.

```
┌────────────────────────────────────────────────────────┐
│                   EXPRESS + WS SERVER                  │
│                      (server.ts)                       │
│                                                        │
│  ┌──────────────────────────────────────────────────┐  │
│  │  Game Room Manager & Authoritative State Engine  │  │
│  │  - Rooms Map (code -> RoomState)                 │  │
│  │  - Prompt Bank (STANDARD + THRIP + 18+/FAMILY)   │  │
│  │  - Matchmaking, Turn Timers, Vote Calculation    │  │
│  └──────────────────────────────────────────────────┘  │
│          ▲ WebSocket                ▲ WebSocket        │
└──────────┼──────────────────────────┼──────────────────┘
           │                          │
           ▼                          ▼
┌─────────────────────────┐  ┌─────────────────────────┐
│     HOST / TV VIEW      │  │    MOBILE CONTROLLER    │
│    (Big Screen / QR)    │  │    (Player Screen)      │
│  - Lobby / Room Code    │  │  - Join Form            │
│  - Head-to-Head Battles │  │  - Prompt Answer Input  │
│  - Live Vote Reveal     │  │  - Vote Buttons         │
│  - Sound Engine (Audio) │  │  - Reaction Pad         │
└─────────────────────────┘  └─────────────────────────┘
```

### Структура состояния комнаты (Room State):
```typescript
interface GameRoom {
  code: string;                 // 4-значный код комнаты (например "MEH1")
  hostSocketId: string;
  phase: 'LOBBY' | 'PROMPT_INPUT' | 'VOTING' | 'ROUND_RESULTS' | 'FINAL_PODIUM';
  settings: {
    tags: ('STANDARD' | '18+' | 'FAMILY')[];
    types: ('STANDARD' | 'THRIP')[];
    timerSeconds: number;
    roundsCount: number;
  };
  currentRound: number;
  players: Player[];
  promptsForRound: AssignedPrompt[];
  answers: Record<string, PlayerAnswer>;
  votes: Record<string, string[]>; // promptId -> array of voter playerIds
  scores: Record<string, number>;
}
```

### Обработка отключений и отказоустойчивость:
- Автоматическое переподключение клиента при кратковременном обрыве связи с сохранением сессии игрока по `playerId` в `sessionStorage`.
- Возможность запустить демонстрационный режим ("Добавить ботов / тест") для мгновенной проверки игры одним человеком без ожидания реальных друзей.

## 4. План реализации по шагам

1. **Серверная часть и WebSocket протокол (`server.ts`)**:
   - Настройка HTTP сервера на порту 3000 с поддержкой Vite middleware в dev-режиме и статической раздачи в prod.
   - Инициализация WebSocket сервера (`ws`) с обработкой комнат, генерацией 4-буквенных кодов, событий `ROOM_CREATE`, `PLAYER_JOIN`, `START_GAME`, `SUBMIT_ANSWER`, `SUBMIT_VOTE`, `TRIGGER_REACTION`.
   - Внедрение базы вопросов из предоставленного файла `mehlist_b03b2d30.txt` с возможностью расширения через API.

2. **Клиентская архитектура и маршрутизация экранов**:
   - Главный селектор режима: «Создать комнату (Экран для ТВ)» или «Войти в игру (Экран игрока)».
   - Поддержка параметров URL (например, `?room=CODE` при сканировании QR-кода сразу открывает экран входа).

3. **Компоненты главного экрана (Host / TV)**:
   - `LobbyView`: крупный код, стильный QR-код (через чистый SVG без внешних библиотек), список игроков, фильтры тегов/типов.
   - `AnsweringView`: таймер с круговым прогресс-баром, карточки игроков со статусом «Думает...» / «Ответил!».
   - `ShowdownBattleView`: анимация вылета двух карточек ответов, сравнение, анонимность авторов до завершения голосования.
   - `VoteRevealView`: взрывной показ голосов, начисление очков, праздничный звук и медали.
   - `PodiumView`: церемония награждения, самый смешной ответ игры («Золотой Мех»), кнопка перезапуска.

4. **Компоненты мобильного контроллера (Player View)**:
   - Удобная клавиатурная форма для ввода ответа на задание.
   - Для заданий типа `THRIP` — 3 отдельных аккуратных поля ввода («1», «2», «3»).
   - Экран голосования с крупными контрастными кнопками выбора лучшего ответа.
   - Экран реакций со всплывающими эмодзи (смех, огонь, фейспалм, хлопки), передающимися на ТВ-экран.

5. **Звуковой движок и полировка интерфейса**:
   - Синтезатор звуковых эффектов на Web Audio API (не требует внешних mp3 файлов, мгновенно работает оффлайн и без задержек).
   - Проверка сборки (`compile_applet`, `lint_applet`) и запуск сервера.
